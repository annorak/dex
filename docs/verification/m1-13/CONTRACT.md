# M1-13 contracts

Status: implemented and independently reviewed at the product head in REPORT.md. No process reference exists. M1-14 is not part of this change.

`dex eval --scenario tests/scenarios/score-*.json --out RUN` freezes independently written keys and immutable execution bytes before invoking the existing checked scenario executor. The executor receives programs, admitted sources, facts, company, cohort, business date and cutoff. It receives no expected answers. The bundle bridge compares the supplied learning view with the existing projection of the admitted bundle. Exam facts are released only to evaluator-owned frozen execution. Learning artifacts retain their original exclusion rules.

A complete outcome contains decision, effects and waits. Canonical values preserve types and complete payloads. Missing required results stay in the independent denominator. A legitimate expected wait has no error. Historical mismatches, reference errors, required unresolved cases and copied corrupted fields retain separate exact case sets and field differences. Duplicate mistake pointers are invalid.

Arrival context is selected from observed, received and available historical facts at arrival. Earlier candidate output is not an input to later cases. Occurrence, observation, receipt, availability and effective dates remain distinct evidence.

A saved run contains freeze, actual, expected, score, ledger, coverage and costs artifacts plus a content manifest. Publication requires a fresh destination. Valid evaluation failures return status 1 with a complete saved run. Invalid inputs return status 2 without a run. Key-tamper controls record changed and missing file diagnostics before execution, preserve case metadata as not started, and mark the cases not scored. They do not manufacture an execution result.

The activity ledger contains supplied synthetic historical records. It does not claim that this evaluation performed those actions. Every row carries that provenance. Model records bind an exact request, work revision, program, recording and delivery time. Logical invocations, network calls, retries, tokens and costs remain separate. Current evaluation activity is reported separately under costs.execution_activity. No live model network calls are used.

Distinct human identity is company, origin and action ID. Redelivery is deduplicated; conflicting reuse is rejected. Combined review and exact-change approval retain both tags and count once. Primary categories distinguish business authority, case review, requested input, exact-change approval, compile clarification, program approval and authority administration. Supplied records cannot approve a program, grant authority, or complete an effect.

Event weeks begin Monday in the recorded event offset. Week, version and intersection buckets name their exact case sets and denominator. Zero-activity cases enter their opening week and initial program version. Shared compile and administrative actions have separate buckets. There is no amortization. All, started, completed, pending and not-started cohorts are separate.

`dex report RUN` verifies recorded hashes and reads saved outcomes. It does not execute programs, regenerate keys or call models. Repeated reports in fresh processes must preserve bytes and identities. An optional measurement supplement binds the run identity and exact workload; its own hash is reported separately and it cannot change the recorded outcome. Failed measurement samples remain visible.

The engine manifest covers reusable package content, including core, workspace, ordinary adapters, bundle admission, codecs and verification. It also explicitly covers the shared scenario parser, executor, serializer and frozen execution boundary. Runtime dependency requirements, installed versions and content hashes are included. Evaluator, demo and reference artifacts are separate. Evidence changes do not alter engine identity. A later reference must reuse this engine manifest or disclose a changed engine.

All acceptance document paragraphs are enumerated by content identity. Requirements without execution evidence remain unimplemented. Process references, learned-stream results and full process acceptance gates remain unavailable. Fixture totals remain requirements until executed.

Performance uses exactly 10,000 cases and 100,000 supplied ledger events. The evaluator performs 10,000 checked function calls; report processes all cases and all events. Limits remain scoring 10 seconds, report 5 seconds, combined completion 20 seconds and RSS 1 GiB. Timer V2 measures full commands separately; scoring_ns measures only scoring and lists exclusions. Supported regression workloads are CLI help and language-arithmetic, selected because this change touches CLI dispatch and the shared scenario executor. Generator code and generated bytes are unchanged, so the historical generation matrix is not repeated. The independent verifier freezes exact revisions, commands, inputs, schedule and environment before formal samples. Every sample is retained.
